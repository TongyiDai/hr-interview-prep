# 通用材料整理

本 Skill 可以在没有招聘系统接口的情况下运行。Agent 的任务是把用户已经提供的材料整理成岗位证据，再交给结构化面试包生成器。

## 输入来源

按以下顺序处理：

1. 当前对话中的岗位目标、招聘负责人要求和面试约束。
2. 用户明确提供的本地文件：Markdown、纯文本、JSON、CSV、XLSX、DOCX、PDF、邮件导出或聊天导出。
3. HR 提供的历史面试题、评分表、复盘记录和招聘规范。
4. 用户明确授权的外部系统，例如飞书、ATS、HRIS、云盘或知识库。

先使用已经在手边的材料。外部连接器只补充缺口，不替代本地证据。

## 抽取方法

把材料分成四类：

- 岗位事实：关键工作结果、职责、级别、硬性要求和协作关系。
- 评价规则：组织批准的能力定义、面试轮次、评分锚定和合理调整规则。
- 观点与偏好：招聘负责人或面试官的看法，保留说话人和“待确认”状态。
- 候选人信息：姓名、联系方式、简历、逐字稿和个人属性。默认排除，不进入岗位设计输入。

每条岗位判断都尽量记录：

```text
来源：local_markdown / chat_export / hr_note / spreadsheet / user_statement / connector
来源标识：用户可复核的文件名、消息主题或脱敏资源标识
事实：材料明确写了什么
可支持的判断：可以据此设计哪项岗位胜任力或面试约束
状态：已确认 / 待确认 / 存在冲突
```

观点不能直接升级为岗位要求。多个来源冲突时并列呈现，交给招聘负责人确认。

## 文件处理边界

- 能直接读取的文本先做局部读取，避免把整份历史聊天或整本候选人材料带入上下文。
- DOCX、PDF、XLSX 等格式依赖当前 Agent 的文件能力；无法解析时要求用户提供文本或结构化导出。
- 邮件和聊天记录只提取与岗位结果、能力标准和面试安排相关的内容，保留必要的时间和来源标识。
- 原始文件留在用户自己的位置；仓库和生成结果只保存脱敏后的岗位结构与来源摘要。
- 输入生成器前，先把材料归一化为 `references/input-schema.md` 中的 JSON 结构。

## 推荐的归一化片段

```json
{
  "source_materials": [
    {"id": "role-brief", "type": "local_markdown", "label": "岗位说明.md", "status": "已确认"},
    {"id": "hr-chat", "type": "chat_export", "label": "招聘负责人消息导出", "status": "待确认"}
  ],
  "role": {
    "title": "产品经理",
    "level": "中级",
    "outcomes": ["明确用户问题并推动产品交付"],
    "constraints": ["需要与研发、设计和销售协作"]
  }
}
```

`source_materials` 只记录来源摘要，不放原文、候选人个人信息、访问令牌或本地绝对路径。
