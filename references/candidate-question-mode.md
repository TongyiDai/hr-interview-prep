# 候选人针对性追问模式

这是岗位面试包的可选第二层。它读取已经完成的岗位面试设计和脱敏后的候选人工作经历摘要，生成面试官可以使用的核验问题。HR 可以提供原始简历，但 Agent 必须先在授权环境中临时抽取并脱敏；生成器不直接保存或处理原始简历全文。

## 两层关系

| 层级 | 输入 | 产出 | 是否对所有候选人一致 |
|---|---|---|---|
| 岗位层 | 岗位材料、招聘规范、面试约束 | 胜任力、核心问题、评分锚定、面试官覆盖 | 是 |
| 候选人层 | 脱敏简历中的岗位相关经历 | 针对经历的澄清、核验和证据追问 | 追问内容可不同，评价标准保持一致 |

岗位层必须先完成。候选人层只能补充证据，不能改写岗位胜任力、评分尺度或录用标准。

## 推荐输入

候选人输入使用 `scripts/build_candidate_questions.py` 的 JSON 结构：

```json
{
  "candidate_ref": "candidate-001",
  "experiences": [
    {
      "experience_id": "exp-001",
      "label": "支付产品改版项目",
      "claims": [
        "负责从需求分析到上线的产品推进",
        "推动研发与运营协作完成交付"
      ],
      "related_competencies": ["problem_solving", "collaboration"],
      "evidence_gaps": [
        "本人具体决策和贡献需要核验",
        "结果指标和验证方式未明确"
      ]
    }
  ]
}
```

`candidate_ref` 只使用脱敏编号。`claims` 是从简历中提取的岗位相关主张，不放姓名、联系方式、原始简历全文或候选人的受保护属性。没有候选人编号时，由 Agent 生成短期脱敏编号。

## 问题生成规则

每条简历主张至少围绕以下维度生成追问：

- 背景和目标：当时要解决什么问题，成功如何定义。
- 本人贡献：候选人亲自负责什么，团队成员分别做了什么。
- 决策过程：有哪些选项、约束、权衡和关键判断。
- 结果证据：结果如何衡量，数据从哪里来，是否达到目标。
- 协作与分歧：涉及哪些角色，如何处理目标不一致。
- 复盘迁移：哪些做法可以迁移到当前岗位，哪些经验仍需验证。

输出中每条问题要绑定岗位胜任力和面试轮次，并列出面试官需要记录的事实、证据和未验证项。

## 公平与隐私边界

- 保留同一岗位的核心问题和评分锚定，确保候选人都有机会展示相同的岗位能力。
- 只围绕简历中的工作经历和岗位相关主张追问，不把简历中的学校、地域、年龄、性别、健康、家庭、宗教、民族、婚姻或薪酬信息转成问题。
- 追问用于澄清和核验，不能从“写在简历上”直接推出能力分数。
- 缺少证据时记录“未验证”，不能把沉默或简历缺项当作负面证据。
- 真实候选人材料只在用户授权环境中处理，不进入岗位模板、视觉资产、测试样例或公开仓库；测试只能使用合成数据。
- 任何录用、淘汰、排序和合规判断都由人类依据组织规则完成。
